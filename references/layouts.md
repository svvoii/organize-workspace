# Layout option templates

Present **up to 3** options at runtime, adapted to the user's actual entries. Each option is
shown as an ASCII worktree plus a 2–3 line rationale. The user picks one (or a custom
variant); nothing moves before that confirmation.

## Option A — Domain buckets (best for: many projects/repos, active development)

```
<root>/
├── AGENTS.md / README.md      <- index pair (generated by this skill)
├── <HUB>/                     <- only if the user has one (e.g. WORKSPACE with a kanban)
├── PROJECTS/
│   ├── <DOMAIN-1>/            <- e.g. WEB, AI-ML, OPS, SCHOOL
│   ├── <DOMAIN-2>/
│   └── ...
├── REFERENCE/                 <- books/, certificates/, setups/
├── PRIVATE/                   <- personal life + paperwork
└── FINANCE/                   <- only if sensitive financial material exists (chmod 700)
```

Rationale: root stays shallow and means "active work"; everything else is one level down in
a semantic bucket; domains group projects by topic so finding one is O(1).

## Option B — Active + Archive (best for: one or two active things, lots of stale history)

```
<root>/
├── AGENTS.md / README.md
├── <ACTIVE-1>/                <- only currently-active entries stay at root
├── <ACTIVE-2>/
├── CONTEXT/                   <- reference + personal + paperwork subfolders
└── ARCHIVE/
    └── QUARANTINE-<YYYY-MM-DD>/   <- stale items, moved not deleted; purge is owner's manual call
```

Rationale: minimal root = instant "what am I working on"; history is preserved in a dated
quarantine instead of being deleted; nothing is lost, easy to restore with one `mv`.

## Option C — Work vs Life split (best for: mixed professional + personal content, no heavy project load)

```
<root>/
├── AGENTS.md / README.md
├── WORK/                      <- jobs, CVs, projects, learning
│   ├── PROJECTS/
│   ├── JOB-SEARCH/
│   └── LEARNING/
├── PERSONAL/                  <- travel/, health/, media/, games/
└── ADMIN/                     <- taxes, government, employers (keep indefinitely)
```

Rationale: mirrors how the user thinks (work vs life); paperwork gets its own keep-forever
bucket so it never gets confused with deletable clutter.

## Naming conventions to propose (let the user veto)
- Directory names: ALL-CAPS at root and for bucket/project folders; project-internal content
  keeps its original naming. (Alternative: lowercase-hyphen everywhere — ask the user.)
- No spaces in names; hyphens as separators.
- New items always go into a bucket, never loose at root.
